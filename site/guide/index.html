1

Create a GitHub repository for your exam

Your repository holds everything: research, agents, knowledge and the app. Netlify deploys straight from it.

  1. Go to your GitHub page, click Repositories, then the green New button.
  1. Name it (I used NLPFinal), switch Add README to On, and click Create repository.
2

Open it in Claude Code

Claude Code reads and writes your repository directly.

Before you start: the GitHub connector must be connected in Claude (Customize → Connectors → GitHub Integration with a check mark).

  1. Go to claude.ai/code, click New, click the repository name under the message box and pick your repository.
  2. Click the model name and choose Opus 5.5 with Medium effort. Do not use Fable.
3

Research your NLP use case

Pick a use case where NLTK and spaCy each do what they are best at. The research also has to answer one hard question: what can Netlify actually run?

My worked example is a Customer Review Analyzer. Change the use case to your own (ideas at the bottom of this page), but keep the four research questions.

Paste this into Claude Code
This is my natural language processing final project. Do some research on an NLP use case that uses BOTH NLTK and spaCy in one app. My use case: a Customer Review Analyzer that reads product or restaurant reviews and shows sentiment, key phrases, and the people, places, brands and products mentioned. Research: (1) what NLTK does best for this (tokenizing, stopwords, VADER sentiment, frequency and collocations), (2) what spaCy does best (named entities, noun chunks, lemmas, dependency parsing), (3) a free, public review dataset we can use, and (4) the app MUST be deployed on Netlify, so research exactly what Netlify can and cannot run (build-time Python, Netlify Functions languages, running Python in the browser with Pyodide) and recommend the architecture. Put the results inside a docs folder (one markdown file per topic plus a README index) and push the docs folder to the main branch on GitHub. This is context for a team of expert agents we will build next.

Good to know: This shapes the whole app. spaCy and NLTK run over the dataset at build time and save results as files; NLTK can also run live in the browser through Pyodide. No server is needed, so it all deploys free on Netlify.

Check it worked: On GitHub, open the docs folder and confirm the research files are on main.

4

Decide the roles: who is on your team?

You are the project lead. Ask which experts you need. Two are required: an NLTK expert and a spaCy expert. Netlify limits the rest, so you will not need backend or database roles.

Paste this into Claude Code
Decision: everything must run on Netlify (no outside servers). Use the recommended architecture: NLTK and spaCy run over the review dataset at build time and save results as static files, and NLTK also runs live in the browser with Pyodide for "analyze your own review." Now, if I were leading this project and wanted to surround myself with experts, give me a list of all of the experts (agents) I would need to design, build, test and deploy this app. Two of them MUST be an NLTK expert agent and a spaCy expert agent. Because we deploy to Netlify, keep the roles to what a static site, a Python build step and Pyodide actually need. Also include an orchestrator agent and a meta agent. For each role give a one-line job description, then define the skills they need, showing which agents share each skill. Save it to docs/expert-roster.md and push to main.

Good to know: Think about the roles yourself before you accept them. Would you hire a "Pyodide Engineer"? Why does Netlify make a database administrator unnecessary? You may be asked to explain your team.

5

Build the agents, their skills and their knowledge

Each agent gets its instructions, its skills, a model (its brain), a personality, and a knowledge folder filled with real notes from the official documentation.

Paste this into Claude Code
Read the official Claude Code documentation on subagents (https://code.claude.com/docs/en/sub-agents) and skills (https://code.claude.com/docs/en/skills). Then build every agent from docs/expert-roster.md as a project subagent in .claude/agents/ and every skill as a project skill in .claude/skills/<skill-name>/SKILL.md, wiring each agent to its skills. Then build the knowledge for the agents: create knowledge/<agent-name>/ for every agent and fill it with real reference notes from the official documentation for that agent's job. The NLTK expert gets notes from nltk.org (tokenizers, stopwords, VADER, FreqDist, collocations, data downloads), the spaCy expert gets notes from spacy.io (pipelines, en_core_web_sm, entities, noun chunks, EntityRuler, displaCy), the Pyodide engineer gets Pyodide docs notes, the Netlify engineer gets Netlify build and Python version docs notes, and so on, each with source links. Make every agent read its knowledge folder before answering. Pick the right model for each agent (opus, sonnet or haiku) and give each one a name and personality, listed in a table in docs/agent-brains.md. Add a CLAUDE.md that explains the team. Push everything to main.

Check it worked: On GitHub, open .claude/agents. You should see one file per agent, including nltk-expert.md and spacy-expert.md.

6

Have your agents build the app

Now the team does the work. The orchestrator hands each part to the right expert: NLTK for sentiment and key phrases, spaCy for entities and aspects.

Paste this into Claude Code (change the details to your use case)
@agent-orchestrator Have the team build the Customer Review Analyzer app and make it deploy-ready for Netlify. Use each expert for its part: the dataset curator prepares a small review sample, the NLTK expert writes the NLTK part (tokenizing, stopwords, VADER sentiment, top words and key phrases), the spaCy expert writes the spaCy part (named entities, brands and products with an EntityRuler, noun-chunk aspects like "battery life"), the build pipeline engineer runs both at Netlify build time and saves the results as static JSON, the Pyodide engineer makes NLTK run live in the browser for an "Analyze your own review" box, the frontend and data viz experts build one clean web app with clear labels showing which results come from NLTK and which come from spaCy, the Netlify engineer adds netlify.toml (Python version, build command, publish folder), and the QA engineer and NLP evaluator test it. Run the experts in parallel: launch every expert whose inputs are ready at the same time (and run the peer reviews in parallel too), and only wait when one expert needs another's output. Add a Resources page to the app that lists every link the project relies on (the official documentation for each library, the GitHub repository and the step-by-step guide) and link to it from the app's header or footer. Run the full build locally to prove it works, write a README with deploy steps, and push everything to main.

Good to know: This step is long. You can close the tab and come back; the session keeps working. If the team gets stuck, tell the orchestrator what you see and ask it to fix it.

Check it worked: On GitHub, your repository now has folders like nlp, pipeline, site, tests and reports, plus netlify.toml.

7

Deploy on Netlify

Netlify reads your repository, runs the Python build (NLTK and spaCy), and publishes the site. No API key is needed because the NLP runs at build time and in the browser.

  1. Go to app.netlify.com (sign up free with GitHub if needed). Click Add new project → Import an existing project, then GitHub.
  1. Search for your repository and click it.
  1. Give the project a name (this becomes your URL). Do not change the build settings: Netlify reads them from netlify.toml, including the Python build command.
  2. Click Deploy.

Good to know: If the deploy fails, click the failed deploy, copy the error from the log, and paste it to the orchestrator in Claude Code. Every push to main redeploys on its own.

8

Test your live app

Make sure both libraries are really working on the live site before you submit.

Open your URL (mine: nlpfinal-review-analyzer.netlify.app) and check each part.

Check it worked: Every panel loads, the NLTK and spaCy labels are visible, and the live box returns a result.

Submit your final exam

One app, both libraries, live on Netlify.

Submit: your live Netlify URL (for example https://your-app.netlify.app). Also include your GitHub repository link so your work can be checked.

Requirements

  • One app, live on Netlify, that works when the URL is opened.
  • NLTK is used for a clearly labeled part of the app (for example tokenizing, stopwords, VADER sentiment, word frequency, collocations).
  • spaCy is used for a clearly labeled part of the app (for example named entities, noun chunks, lemmas, dependency parsing, EntityRuler).
  • Your repository has a docs folder with your research, .claude/agents with your team (including an NLTK expert and a spaCy expert), .claude/skills, and a knowledge folder for each agent.
  • The app has a Resources page listing every link the project relies on (official docs, your GitHub repo, the guide).
  • Everything is pushed to the main branch.

Pick your own use case

The review analyzer is the worked example. You may use it, but you will learn more with your own. Ideas that fit NLTK + spaCy on Netlify:

News headline explorer

NLTK: word frequency and sentiment by day. spaCy: who and which organizations are in the news.

Job posting skills finder

NLTK: most common skill words and collocations. spaCy: companies, locations and job titles.

Speech or lyrics analyzer (public domain text)

NLTK: vocabulary richness and sentiment by section. spaCy: people, places and noun phrases.

Support ticket triage

NLTK: sentiment and urgency keywords. spaCy: products and order numbers with an EntityRuler.

Course review insights

NLTK: what students praise or complain about. spaCy: which topics, tools and instructors are mentioned.

Good to know: if something breaks on Netlify, open the deploy log, copy the error, and paste it into Claude Code: "@agent-orchestrator The Netlify build failed with this error: ... Have the Netlify engineer fix it and push to main." Netlify redeploys on its own.
